# AdelFlo 사이트 — 새 구조 설명

## 무엇이 바뀌었나요

- **디자인**: 종이 질감의 크림톤 배경 + 딥그린/클레이 포인트 컬러로 전체적으로 다듬었습니다. 글꼴은 기존 사이트와 동일하게 Arial 그대로 유지했습니다. 상단 탭은 리본형 알약 버튼으로, 갤러리 카드는 그림자와 캡션이 있는 카드 형태로 바뀌었고, 모달과 썸네일도 같은 톤으로 정리했습니다.
- **데이터 분리**: 기존에는 `images` 객체를 JS 코드 안에 직접 한 장씩 작성했지만, 이제 `index.html`은 **`gallery.json`(또는 배포한 API)에서 데이터를 불러와** 화면을 그립니다. 즉, 이미지를 추가할 때 더 이상 HTML/JS 코드를 건드릴 필요가 없습니다.
- **관리자 업로드 (부가 이미지 묶음 지원)**: `admin.html`에서 비밀번호로 로그인한 뒤, 이미지 여러 장을 **한 번에 드래그 앤 드롭**하면 그게 하나의 묶음(항목)이 됩니다. 첫 번째 이미지가 메인, 나머지는 클릭 시 보이는 "부가 이미지(extraImages)"로 들어가며, 어떤 사진을 메인으로 할지 클릭으로 바꾸거나 사진마다 개별 설명을 달 수 있습니다. "마스터 아이디" 같은 회원 시스템 대신, **관리자 비밀번호 하나**로 충분합니다 (개인 사이트에는 이 방식이 훨씬 간단하고 관리하기 쉽습니다).

## 파일 구성

```
index.html     → 메인 갤러리 페이지 (누구나 보는 화면)
login.html     → 관리자 로그인 전용 페이지 (일반 사이트 로그인창처럼 독립된 화면)
admin.html     → 관리자 업로드 페이지 (로그인 후에만 접근, 비로그인 시 login.html로 이동)
gallery.json   → 초기 이미지 데이터 (기존 사이트에서 그대로 옮겨둔 것)
worker.js      → Cloudflare Worker 백엔드 코드
wrangler.toml  → Worker 배포 설정 파일
```

## 왜 백엔드(Worker)가 필요한가요?

정적 HTML 사이트만으로는 "관리자가 올린 이미지가 모든 방문자에게 보이는" 기능을 만들 수 없습니다 (브라우저 저장소는 본인 브라우저에만 남아요). 그래서 이미 사용 중인 **Cloudflare R2**(이미지 저장소)에 더해, 업로드를 처리할 아주 작은 서버 역할을 하는 **Cloudflare Worker**를 하나 추가했습니다. 무료 요금제로 충분히 운영 가능한 규모입니다.

## 배포 순서 (한 번만 하면 됩니다)

1. **Cloudflare 계정**에 로그인 (이미 R2를 쓰고 계시니 계정은 있으실 거예요).
2. 터미널에서 Wrangler 설치 및 로그인:
   ```
   npm install -g wrangler
   wrangler login
   ```
3. `wrangler.toml`의 `bucket_name`을 실제 R2 버킷 이름으로 수정합니다.
   (Cloudflare 대시보드 → R2 → 버킷 목록에서 확인)
4. 관리자 비밀번호를 secret으로 등록합니다:
   ```
   wrangler secret put ADMIN_PASSWORD
   ```
   원하는 비밀번호를 입력하면 됩니다 (사이트 코드에는 저장되지 않아 안전합니다).
5. `worker.js`가 있는 폴더에서 배포:
   ```
   wrangler deploy
   ```
   배포가 끝나면 `https://adelflo-api.본인계정.workers.dev` 같은 주소가 나옵니다.
6. 처음 한 번, 기존 데이터를 R2에 올려둡니다 (R2 대시보드에서 `gallery.json` 파일을
   `data/gallery.json` 경로로 직접 업로드하거나, `wrangler r2 object put` 명령을 사용하세요):
   ```
   wrangler r2 object put 버킷이름/data/gallery.json --file=gallery.json
   ```
7. `index.html`, `login.html`, `admin.html` 맨 위쪽의 `API_BASE` 값에 6번에서 받은 Worker 주소를 넣습니다:
   ```js
   const API_BASE = "https://adelflo-api.본인계정.workers.dev";
   ```
8. 사이트를 기존과 같은 방식(호스팅 중인 곳)에 업로드하면 끝입니다.

## 이후 사용법

1. `admin.html`에 접속하면(또는 링크를 몰라도) 로그인이 안 되어 있는 경우 자동으로 `login.html`로 이동합니다. 여기서 비밀번호를 입력해 로그인합니다.
2. 로그인에 성공하면 자동으로 `admin.html`로 이동합니다.
3. "+ 새 묶음 만들기" 영역에 이미지를 끌어다 놓습니다. **한 번에 여러 장을 같이 놓으면 그게 한 묶음(하나의 항목)이 됩니다.**
4. 자동으로 첫 번째 이미지가 "메인"으로 표시됩니다. 다른 사진을 메인으로 하고 싶으면 그 사진의 "메인으로" 버튼을 누르면 됩니다.
5. 묶음의 탭 / 저장 폴더 / 제목(메인 desc) / 설명(메인 extra)을 입력하고, 부가 이미지들에는 각각 짧은 설명을 달 수 있습니다.
6. 묶음을 더 만들고 싶으면 "+ 새 묶음 만들기"에 다시 드래그하면 새 카드가 추가됩니다. (동시에 여러 묶음 준비 후 한 번에 업로드 가능)
7. "전체 업로드" 버튼을 누르면 각 묶음의 이미지들이 R2에 올라가고, 완성된 항목이 `gallery.json`에 자동으로 추가됩니다.
8. `index.html`을 새로고침하면 바로 반영됩니다.
9. `admin.html`의 "로그아웃"을 누르면 세션이 지워지고 다시 `login.html`로 이동합니다.
10. 비밀번호는 브라우저의 세션 저장소에만 잠깐 저장되고, 탭을 닫으면 사라집니다.

## API 엔드포인트 (worker.js)

- `GET /api/gallery` — 갤러리 데이터 조회 (공개)
- `POST /api/verify` — 비밀번호가 맞는지만 확인 (login.html에서 사용)
- `POST /api/upload-file` — 이미지 파일 1장을 R2에 저장하고 URL 반환 (관리자 전용, gallery.json 미변경)
- `POST /api/add-entry` — 완성된 항목(`{ src, desc, extra, extraImages? }`)을 특정 탭에 추가 (관리자 전용)
- `POST /api/delete` — 특정 탭의 특정 인덱스 항목 삭제 (관리자 전용)

## 참고 / 다음에 더 다듬을 수 있는 부분

- 이미지 순서 변경(드래그로 재배치), 이미 올라간 항목 수정 UI는 아직 없습니다. 필요하면 이어서 만들어드릴게요.
- 항목 삭제 UI는 관리자 페이지에 아직 없고, Worker의 `/api/delete`만 구현되어 있습니다. 필요하면 삭제 버튼도 추가해드릴게요.
- 비밀번호 방식은 개인 운영 사이트에는 충분하지만, 여러 명이 각자 계정으로 로그인해야 한다면 별도 인증 시스템이 필요합니다.
